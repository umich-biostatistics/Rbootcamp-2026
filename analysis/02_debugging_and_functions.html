1. The debugging ladder

When code breaks, do not rewrite the whole script. Move through the ladder.

  1. Reproduce: Can I make the error happen again?
  2. Read: What does the message literally say?
  3. Isolate: Which line first fails?
  4. Inspect: What are the object names, types, dimensions, and missing values?
  5. Test: Which assumption was false?
  6. Verify: Did the fix solve the original problem?

Function scaffold

Complete the function. Keep it small and readable.

summarize_numeric_by_group <- function(data, group_col, value_col, na_rm = TRUE) {
  data |>
    group_by({{ group_col }}) |>
    summarize(
      n = n(),
      mean = mean({{ value_col }}, na.rm = na_rm),
      sd = sd({{ value_col }}, na.rm = na_rm),
      missing = sum(is.na({{ value_col }})),
      .groups = "drop"
    )
}

5. Documentation, search, and AI responsibly

Use AI and search as debugging tools, not as substitutes for running checks.

A good debugging prompt:

I am a beginning R user. This code gives the error below. Please explain what the error means, name the first object or column I should inspect, and suggest the smallest fix. Do not rewrite the full analysis. Code: … Error: …

Before asking for help, prepare a minimal example:

# Not the full data; just enough structure to show the problem.
example_health <- tibble(
  cohort = c("screening", "follow-up"),
  bmi = c(24.1, NA),
  systolic_bp = c(118, 135)
)
Error in `tibble()`:
! could not find function "tibble"

Responsible-use checklist:

  • Do not paste protected health information, credentials, or sensitive unpublished data into third-party AI tools.
  • Share the error, the relevant line, and fake or simulated example data.
  • Verify suggestions by running code and checking objects with str(), glimpse(), names(), and ?function_name.
  • Ask for help when you cannot isolate the failing line, when a result changes unexpectedly, or when the code affects real analysis decisions.
